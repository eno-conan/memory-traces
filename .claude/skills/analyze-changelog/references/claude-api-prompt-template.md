## 重要な判定基準（アクション可能性フィルタ）

CHANGELOG差分を以下の基準で厳密にフィルタリングし、**アクション可能な項目のみ**を分析対象としてください:

### 分析対象にする（アクション可能）
- **新機能の追加**: 新しい設定オプション、コマンド、ツール、プラグインなど
- **既存機能の仕様変更**: ユーザーが設定を変更すべき内容、動作の変更
- **新しいベストプラクティス**: ドキュメント化された推奨パターンや使い方
- **`.claude`ディレクトリで活用できる機能**: agents, rules, skills, commands, settings.jsonに反映できる内容

### 分析対象外（アクション不可能）
- **Claude Code内部の実装変更**: UI改善、エディタ統合、内部アーキテクチャ
- **バグ修正**: 既存機能の不具合修正（ユーザー側での対応不要）
- **パフォーマンス改善**: メモリ管理、セッション安定性、処理速度の向上
- **内部処理の改善**: ユーザー側で制御できない内部ロジック
- **エラーメッセージや通知の改善**: 表示内容の変更のみ

### 判定例
- NG: "コンテキストウィンドウのブロック制限が約65%から約98%に修正" → バグ修正
- OK: "Task機能の追加（~/.claude/tasksに永続化、依存関係管理）" → 新機能
- NG: "長時間セッションの安定性向上" → 内部改善
- OK: "settings.jsonに新しいプラグイン設定オプション追加" → 設定変更

**重要**: 上記の判定基準に基づき、**人間がリポジトリで実際にアクションを起こせる内容のみ**を提案してください。

## 除外ルール（厳格適用）

以下の内容は**絶対に提案に含めないでください**:
- Claude Code内部の実装変更
- バグ修正やパフォーマンス改善
- このリポジトリで使用していない技術やツール
- 具体的なアクションを伴わない情報の羅列
- 「～が改善されました」という報告のみで、ユーザーが何もする必要がない内容

**提案の質を高めるために**:
- 各提案には「ユーザーが具体的に何をすべきか」を明示すること
- 変更前後のコード例を必ず含めること
- 「この機能が追加されたので、このように活用できる」という形で提案すること

## 使用方法

Claude API呼び出し時のパラメータ:
- **モデル**: `claude-sonnet-4-5-20250929`
- **最大トークン**: 8000
- **エラーハンドリング**: リトライ最大3回、指数バックオフ
