# 環境変数管理規約（必須）

## 対象範囲
本ルールは、プロジェクトの環境変数テンプレートファイルに適用される。

- `.env.example` ファイルのみ
- 環境変数の追加・更新・削除

---

## 絶対ルール（違反禁止）

### 1. 既存の環境変数名を変更してはならない

**環境変数名の変更は、すでに設定済みの `.env.local` やデプロイ環境の設定を破壊する可能性がある。**

❌ 禁止例：
```bash
# Before
NEXT_PUBLIC_USER_POOL_ID=

# After（名前変更）
NEXT_PUBLIC_COGNITO_USER_POOL_ID=  # ❌ 既存の変数名を変更
```

✅ 許可される操作：
- コメントの追加・修正
- デフォルト値の更新（空白から空白以外への変更は慎重に）
- セクションコメントの改善

---

### 2. 環境変数を追加する前にユーザーの承認を得ること

**新しい環境変数の追加は、以下の影響を伴う：**
- `.env.local` への追加作業が必要
- CI/CD 環境への設定追加が必要
- チーム全体への周知が必要

❌ 禁止例：
```bash
# いきなり追加する
NEXT_PUBLIC_NEW_FEATURE_FLAG=
NEW_API_ENDPOINT=
```

✅ 必須手順：
1. **ユーザーに質問する**
   - 変数名の提案
   - 用途の説明
   - 必須/任意の区分
   - デフォルト値の有無

2. **承認後に追加する**
   - 適切なセクションに配置
   - わかりやすいコメントを付与

**質問テンプレート例：**
```
以下の環境変数を .env.example に追加してもよろしいですか？

変数名: NEXT_PUBLIC_FEATURE_FLAG
用途: 新機能フラグの有効/無効切り替え
必須/任意: 任意
デフォルト値: false
配置セクション: # Feature Flags

追加してよろしければ承認してください。
```

---

### 3. 環境変数の削除は必ずユーザーの承認を得ること

**環境変数の削除は、既存の設定や機能を破壊する可能性がある。**

❌ 禁止例：
```bash
# コード内で使われていないと判断して削除
# DEPRECATED_API_KEY=  # ❌ 無断で削除
```

✅ 必須手順：
1. 削除理由を明示
2. 影響範囲を調査
3. ユーザーの承認を得る

---

### 4. セクション構造を維持すること

**`.env.example` は機能ごとにセクション分けされており、構造を保つこと。**

現在のセクション構造：
- `# AWS Cognito Configuration`
- `# Cognito OAuth Configuration`
- `# AWS Region`
- `# Google OAuth Configuration`
- `# Cloudflare Workers API`
- `# Cloudflare Account (for Terraform and API management)`
- `# Cloudflare D1 Database`
- `# Cloudflare R2 Photo Storage`

新規セクションを追加する場合は、ユーザーの承認を得ること。

---

### 5. 機密情報を含むデフォルト値を設定してはならない

**`.env.example` は Git にコミットされる公開ファイルである。**

❌ 禁止例：
```bash
GOOGLE_CLIENT_SECRET=actual-secret-value-here  # ❌ 機密情報を含む
CLOUDFLARE_API_TOKEN=real-token-12345  # ❌ 実際のトークンを設定
```

✅ 必須：
```bash
GOOGLE_CLIENT_SECRET=
CLOUDFLARE_API_TOKEN=
# または説明的なプレースホルダー
API_KEY=your-api-key-here
```

## 実装前セルフチェック（必須）

- [ ] 既存の環境変数名を変更していない
- [ ] 新規変数の追加についてユーザーの承認を得た
- [ ] 変数削除についてユーザーの承認を得た
- [ ] 適切なセクションに配置している
- [ ] わかりやすいコメントを付与している
- [ ] 機密情報を含むデフォルト値を設定していない
- [ ] セクション構造を維持している

---

## このルールの背景

> **環境変数の変更は、開発・本番環境すべてに影響する**

環境変数の不適切な管理は以下を引き起こす：

* 本番環境での設定ミスによるサービス停止
* チームメンバーの `.env.local` 設定漏れ
* CI/CD パイプラインの失敗
* 機密情報の誤コミット
* デプロイ環境との設定不整合

**環境変数は「コードの一部」ではなく「環境の設定」である。**
変更は慎重に、かつユーザーの明示的な承認のもとで行うべきである。

---

## 運用上の扱い

本ルール違反は以下として扱う：

* 高リスクな設定破壊
* マージブロッカー
* 即時修正対象

**特に以下は重大な違反とする：**
- 無断での環境変数名変更
- 機密情報を含むデフォルト値の設定
- ユーザー承認なしでの変数追加・削除

---

## 例外条項

以下の場合のみ、ユーザー承認なしでの変更を許可する：

1. **コメントの改善** - 既存変数の説明をわかりやすくする
2. **タイポ修正** - コメント内の誤字・脱字修正
3. **フォーマット統一** - 空白行やインデントの調整

**ただし、変数名・セクション構造には一切触れないこと。**
