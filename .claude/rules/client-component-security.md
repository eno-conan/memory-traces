# Client Component セキュリティ規約（必須）

## 対象範囲
本ルールは、以下のブラウザ実行コードに適用される。

- `use client` が付与された Component
- `app/**/page.tsx`
- `app/**/layout.tsx`
- `components/**`

---

## 絶対ルール（違反禁止）

### 1. 本来サーバーで行うべき処理を Client に書いてはならない
以下の処理を Client Component に実装することを禁止する。

- 認可・権限判定
- ユーザー ID / 組織 ID の信頼判断
- データ整合性を保証する処理
- 秘密情報に基づく分岐

❌ 禁止例：
```ts
if (user.role === "admin") {
  deleteUser(targetUserId);
}
````

---

### 2. Client 側の制御は UX 上の補助に過ぎない

Client 側の条件分岐・非表示は
**セキュリティ的な保証にならない**。

```ts
// 表示を隠しているだけでは防御にならない
{isAdmin && <DeleteButton />}
```

---

### 3. Client 側の判断結果をサーバーは信用してはならない

Client から送信される以下の情報は **常に不正とみなす**。

* 権限フラグ
* ロール
* 所有権情報
* 判定結果

---

### 4. 機密情報を Client Component に保持してはならない

以下を state / props / 変数として保持することを禁止する。

* アクセストークン
* 内部 ID（推測可能でないもの）
* 権限情報の完全データ
* サーバー内部エラー内容

---

## 実装前セルフチェック（必須）

* [ ] Client に認可・権限判断を書いていない
* [ ] セキュリティ上重要な処理は Server にある
* [ ] Client の状態は表示・操作の補助に限定されている
* [ ] Client で持つ情報は漏洩しても問題ない

---

## このルールの背景

> **ブラウザで実行されるコードは、すべて改ざん可能である**

Client 側にロジックを置くと：

* DevTools で即回避される
* 不正操作が容易になる
* セキュリティ境界が崩壊する

---

## 運用上の扱い

本ルール違反は以下として扱う：

* セキュリティ欠陥
* マージブロッカー
* 設計見直し必須
