# あしあと機能 要件定義

## 概要

「あしあと」は旅行・外出の記録を写真とともに管理する機能。
写真のアップロードをトリガーに、EXIF 情報（位置情報・撮影日時）を自動抽出し、
記録を作成・管理する。

---

## 機能要件

### FR-001: あしあと登録

**概要:** 写真をアップロードしてあしあとを作成する。

**ユーザーストーリー:**
ログインユーザーとして、写真をアップロードすることで、位置情報・撮影日時が自動入力された
あしあとを作成したい。

**詳細要件:**
- FR-001-1: ユーザーは画像ファイルをアップロードして新しいあしあとを登録できる。
- FR-001-2: アップロード時にタイトル・感想・撮影日時・位置情報（緯度・経度）を入力できる。
- FR-001-3: 写真の EXIF データから位置情報・撮影日時を自動抽出し、フォームに反映する。
- FR-001-4: 1つのあしあとに複数の写真を紐付けられる（エントリー単位で管理）。
- FR-001-5: 写真は Cloudflare R2 に保存する（キー構造: `{userId}/{dateFolder}/{timeFolder}/{timestamp}-{photoId}.{ext}`）。
- FR-001-6: あしあとメタデータは Cloudflare D1 の `travel_entries` テーブルに、写真メタデータは `photo_metadata` テーブルに保存する。
- FR-001-7: アップロード可能なファイル形式は画像ファイル（JPEG、PNG 等）に限定する。マジックバイト検証を行う。
- FR-001-8: 登録はログイン済みユーザーのみ実行できる（未認証の場合は 401 を返す）。

**API:**
- `POST /api/upload-photo` (FormData: `image`, `userId`, `entryId`, `photoId`, `dateFolder`, `timeFolder`, `latitude`, `longitude`, `title`, `thoughts`, `shotAt`)

---

### FR-002: あしあと一覧（List 形式）

**概要:** ログインユーザー自身のあしあとをテーブル・カード形式で一覧表示する。

**ユーザーストーリー:**
ログインユーザーとして、自分のあしあと一覧をページングと検索フィルターを使って
テーブル形式で閲覧したい。

**詳細要件:**
- FR-002-1: ログインユーザー自身のあしあとのみを表示する（他ユーザーのデータは表示しない）。
- FR-002-2: 一覧はページング表示とする（1 ページあたり 6 件）。
- FR-002-3: 年（year）でフィルタリングできる。
- FR-002-4: タイトル・感想を対象にキーワード検索できる（デバウンス処理あり）。
- FR-002-5: デスクトップではテーブル形式、モバイルではカード形式で表示する。
- FR-002-6: 各エントリーには「詳細へのリンク」「削除ボタン」を表示する。
- FR-002-7: エントリーには代表写真（サムネイル）・タイトル・感想・撮影日を表示する。
- FR-002-8: API の最大ページサイズは 50 件とする。

**API:**
- `GET /api/travel-entries?page={n}&pageSize={n}&year={yyyy}&keyword={text}`
- レスポンス: `{ success, entries[], pagination: { currentPage, pageSize, totalCount, totalPages, hasMore } }`

---

### FR-003: あしあと一覧（Map 形式）

**概要:** ログインユーザーのあしあとを Google Maps 上にマーカーで表示する。

**ユーザーストーリー:**
ログインユーザーとして、自分のあしあとを地図上で視覚的に確認したい。

**詳細要件:**
- FR-003-1: 位置情報（緯度・経度）が登録されているあしあとを地図上にマーカーで表示する。
- FR-003-2: マーカーをクリックすると、そのあしあとの詳細パネルを表示する。
- FR-003-3: 詳細パネルにはタイトル・写真・撮影日を表示する。
- FR-003-4: ユーザーの現在地を取得して地図に表示する機能を提供する。
- FR-003-5: List 形式と Map 形式はタブで切り替えられる（同一ページ内）。

---

### FR-004: あしあと詳細

**概要:** 個別のあしあとの詳細情報を表示する。

**ユーザーストーリー:**
ログインユーザーとして、あしあとの詳細（写真・感想・位置情報）を確認したい。

**詳細要件:**
- FR-004-1: タイトル・感想・撮影日時・位置情報（緯度・経度）を表示する。
- FR-004-2: 紐付けられた複数の写真をカルーセル形式で表示する。
- FR-004-3: 写真は Cloudflare R2 の Public URL で表示する。
- FR-004-4: 詳細画面へのアクセスはログイン済みユーザーのみ可能。
- FR-004-5: 他ユーザーのあしあとは閲覧できない（所有権確認）。

**ルーティング:**
- `/detail/[id]`（Next.js App Router）

---

### FR-005: あしあと削除

**概要:** あしあとを削除する（写真データを含む）。

**ユーザーストーリー:**
ログインユーザーとして、一覧画面から不要なあしあとを削除したい。

**詳細要件:**
- FR-005-1: 削除前に確認ダイアログ（AlertDialog）を表示する。
- FR-005-2: 削除はログイン済みユーザーのみ実行できる（未認証の場合は 401 を返す）。
- FR-005-3: 自分のあしあとのみ削除できる（他ユーザーのデータは削除不可）。所有権は Workers 層で検証する。
- FR-005-4: D1 の `travel_entries` レコードを削除する（ON DELETE CASCADE により `photo_metadata` も連動削除）。
- FR-005-5: R2 に保存された写真ファイルをベストエフォートで削除する（R2 削除失敗は致命的エラーとしない）。
- FR-005-6: 冪等性を保証する（404 も成功として扱う）。
- FR-005-7: 削除エラー発生時はユーザーに通知する（ポップアップ）。

**API:**
- `DELETE /api/travel-entries/[id]`
- リクエストボディ: `{ userId: string }`
- バリデーション: `id` は UUID 形式チェック必須

## データモデル

### あしあと（travel_entries）

| カラム | 型 | 説明 |
|----------|------|------|
| `id` | TEXT (UUID) | 主キー |
| `user_id` | TEXT | 所有ユーザーID（外部キー: users.id） |
| `title` | TEXT | タイトル（必須） |
| `thoughts` | TEXT | 感想（任意） |
| `r2_folder` | TEXT | R2内のフォルダパス（必須） |
| `shot_at` | TEXT | 撮影日時（ISO 8601、任意） |
| `created_at` | TEXT | 作成日時（自動） |
| `updated_at` | TEXT | 更新日時（トリガーで自動更新） |

### 写真メタデータ（photo_metadata）

| カラム | 型 | 説明 |
|----------|------|------|
| `id` | TEXT (UUID) | 主キー |
| `user_id` | TEXT | 所有ユーザーID（外部キー: users.id） |
| `r2_key` | TEXT | R2 オブジェクトキー |
| `latitude` | REAL | 緯度（EXIF から抽出、任意） |
| `longitude` | REAL | 経度（EXIF から抽出、任意） |
| `uploaded_at` | TEXT | アップロード日時（自動） |
| `entry_id` | TEXT | 関連エントリーID（外部キー: travel_entries.id、任意） |

## システム構成（概要）

```
[クライアント（Next.js）]
    ↓ 認証: AWS Cognito / Amplify
[BFF 層（Next.js Route Handlers）]
    ↓ API 転送
[Cloudflare Workers（photo-upload-api）]
    ├── Cloudflare D1（travel_photo_management）
    └── Cloudflare R2（travel-photos）
```

---

## 認証・認可方針

- すべての操作はログイン済みユーザーのみ実行可能
- BFF 層で AWS Cognito セッションを検証し、`userId` はサーバー側で取得する（クライアントから受け取った値は信頼しない）
- Workers 層でデータの所有権（`user_id` 一致）を確認する
